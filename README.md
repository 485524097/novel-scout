# Novel Scout — 小说排雷 AI Skill

> 在你花几十个小时看一本小说之前，先排个雷。

Novel Scout 是一个面向**中文小说 / 网络小说**的**低剧透 AI 排雷 Skill**。给它一本小说，它会先联网核验真实信息，再检查后宫、NTR、虐主、圣母、降智、烂尾等常见小说毒点，并结合你的阅读偏好，判断这本书到底适不适合你。中文网文排雷，先从证据开始。

它不会靠「模型记忆」直接下结论——**先有证据，再有结论**。

## 30 秒上手

把下面任一句话直接发给支持 Agent Skill 的 AI 即可：

```text
排雷《玄鉴仙族》
《XXX》有后宫吗？
《XXX》有没有 NTR？
《XXX》虐主严重吗？
《XXX》适合我吗？
```

## 输出长什么样（虚构示例，仅演示格式）

```text
《雾城拾荒记》（虚构示例，不是真实排雷结论）

后宫：低风险
NTR：未发现明确证据
虐主：中等
主角风格：偏果断
完结状态：连载中

结论：如果你比较介意后宫和 NTR，目前公开信息中没有发现明显高风险项。

剧透等级：轻
```

## 核心特点

- 🔎 **联网核验**：搜索并打开真实页面取证，而不是靠模型记忆
- 🚧 **尽量低剧透**：默认回答「有没有这个雷」和大致严重程度，而不是雷发生在哪一章
- ⚠️ **覆盖常见网文雷点**：后宫、NTR、系统、圣母、虐主、降智、慢热、水文、烂尾等
- 🎯 **支持指定雷点查询**：只想查一个点，就只查一个点，轻量快速
- 👤 **可结合个人阅读偏好**：配置你的硬雷，判断这本书是否适合你
- 📚 **先确认是哪一本**：同名小说先消歧，避免排错书


## 常用请求

| 请求 | 效果 |
|---|---|
| `排雷《XXX》` | 默认完整排雷（轻度剧透、普通详细度） |
| `无剧透排雷《XXX》` | 完全不剧透的完整排雷 |
| `《XXX》有后宫吗？` | 只回答这一个问题，轻量快速 |
| `《XXX》有 NTR 吗？` | 只回答这一个问题，轻量快速 |
| `详细排雷《XXX》` | 更详细的报告 |
| `《XXX》适不适合我？` | 按你的个人偏好判断（未配置偏好时给出通用画像） |

## 它检查哪些雷点

中文网文读者常说的「网文排雷 / 小说避雷」关注点：

- 感情线与后宫（单女主 / 多女暧昧 / 明确后宫 / 无感情线）
- NTR / 感情背叛风险
- 系统存在感
- 主角圣母倾向
- 主角智商与行为逻辑
- 虐主程度
- 慢热 / 水文 / 重复套路
- 剧情逻辑
- 世界观规模
- 力量体系稳定性
- 连载状态与完结信息
- 结局评价（是否两极、是否被普遍视为烂尾）

## 它不是什么

Novel Scout **不是**：

- 小说下载器；
- 小说阅读器；
- 自动追更工具；
- 单纯的小说总结器；
- 通用图书推荐系统。

它的核心任务只有一件：**帮你在开书前或阅读过程中，判断这本书有没有你在意的雷。**

## 个人偏好（可选）

没配置偏好也能用——此时输出客观阅读画像，不做个性化建议。想拿到针对你的建议，复制模板再修改：

```
config/preferences.example.yaml  →  config/preferences.yaml
```

示例（仅展示格式，不是推荐值）：

```yaml
version: 1

spoiler_level: light
detail_level: normal

hard_no:
  - ntr
  - harem

dislike:
  - heavy-system

like:
  - large-worldbuilding

output:
  show_confidence: true
  show_sources: true
```

说明：

- `hard_no` 是硬雷：一旦确认，最终建议直接是「不推荐」，不会被其他加分项抵消
- **`preferences.example.yaml` 只是模板**，只有 `config/preferences.yaml` 会被当作你的真实偏好
- **当前请求优先**：本次说「这次慢热没关系」，就以本次请求为准，配置文件不会被自动修改

## 剧透控制

- `none`：无剧透（不透露关键死亡、最终伴侣、最终 Boss、身份反转、结局事件）
- `light`：轻度剧透（默认，允许结构级方向）
- `full`：完整剧透（仅在你明确要求时使用）

报告开头会标注当前剧透等级与信息截至日期。

## 证据与来源

- 所有结论基于真实检索证据；重要强结论优先通过实际页面核验
- 区分官方、可靠资料、社区和弱来源，不把搜索摘要冒充已打开的页面
- 来源标题本身可能含剧透时，报告会脱敏处理
- 连载作品会标注「截至 YYYY-MM-DD」，不会把当前状态写成永久事实

## 局限性（请先读）

Novel Scout 的判断**依赖公开网络信息**：

1. **冷门小说可能资料不足**——此时会直接说「无法确认」，而不是硬猜
2. **连载小说的雷点/感情线会随剧情变化**——结论带时间边界，可能过时
3. **社区讨论可能存在误传**——「没有搜到证据」不等于严格意义上的「绝对不存在」
4. **对高风险结论会给出证据来源和置信度**——但对「好不好看」「是否烂尾」输出的是社区评价倾向，不是客观真理
5. **不下载、不解析整本小说正文**——调查基于公开资料，不保证覆盖正文中未被讨论的内容
6. **V1 不提供小说推荐，也不做多书比较**——只排雷，不生成书单；「哪本更适合我」需要逐本排雷自行对比

> 不要把它当成 100% 准确的排雷机器：它能帮你把「大概率踩雷的书」筛掉，也会诚实告诉你它不知道的东西。

## 常见问题

### Novel Scout 会剧透吗？

默认尽量不剧透。它回答的是「有没有这个雷、大概多严重」，而不是「雷发生在哪一章、谁和谁发生了什么」。需要完整剧透时才在你明确要求下展开。

### 它的信息可靠吗？

它优先联网查找公开证据，不把模型记忆直接当成事实；多个来源冲突时会如实并列，不替你投票；证据不足时明确说「无法确认」。

### 可以只查一个雷点吗？

可以。直接问「《XXX》有后宫吗？」或「《XXX》有没有 NTR？」，它只查目标雷点并直接回答。

### 可以保存我的阅读偏好吗？

可以。把 `hard_no` / `dislike` / `like` 等字段写到 `config/preferences.yaml`，Skill 会在需要时读取，从而跨会话持久化你的阅读偏好。注意：

- 单次聊天中的临时偏好优先于配置文件（比如本次说「这次慢热没关系」）；
- Skill 不会因为一次对话自动修改 `preferences.yaml`；
- 没配置时也能用（通用客观排雷）。

## 工作原理（简版）

1. 确认你说的是哪一本小说（身份优先，同名作品会请你消歧）
2. 搜索官方与读者来源，打开真实页面核验
3. 区分事实、读者评价和模型判断，逐条记录来源
4. 对冲突信息做交叉验证，按严格标准分类并标注置信度
5. 如果配置了偏好，再判断是否踩你的雷（偏好不改事实判定）
6. 按剧透等级生成排雷报告

核心原则是**证据先于结论**：不靠模型记忆下结论、一个读者评论不代表社区共识、**「无法确认」是合法结果**。

## novel-scout-roast（可选变体）

`novel-scout-roast` 与主 Skill 使用**完全相同**的证据标准与研究流程，仅报告层改为**锐评/吐槽口吻**（严谨证据 + 搞笑吐槽）。

- **依赖**：需要主 `novel-scout` 的 `references/`（taxonomy / source-policy / search-playbook / preference-guide），外加自身 `references/report-format-roast.md`
- **安装**：把整个仓库复制到 Skills 目录即可（roast 会自动复用同级 `references/`）；或把 `novel-scout` 与 `novel-scout-roast` 两个目录作为同级兄弟安装到 `~/.claude/skills/` 下
- **使用**：`锐评《XXX》` / `《XXX》毒舌点评`（触发词见其 SKILL.md）
