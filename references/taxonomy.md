# Novel Scout Taxonomy

> 本文件是 Novel Scout 的统一雷点术语体系：标准 ID、判定规则与边界情况。
> 所有搜索、判断、测试与报告必须使用本文件的术语与 ID。
> 本文件不负责搜索方法与来源判断（见 source-policy.md，搜索方法见 search-playbook.md）。
> 依据：docs/DESIGN.md《雷点分类体系（taxonomy.md）》《绝对禁止的错误》。

## 1. Purpose

Novel Scout 的标签不是文学批评体系，而是一套**面向普通网络小说读者的阅读风险标签系统**。

目标：

- 统一术语：所有分析使用相同 ID，避免"后宫/种马/多女主"混用。
- 明确判定边界：什么情况能判、什么情况不能判。
- 可测试：每个标签都有可核对的判定规则，幻觉测试可依据本文件验证。

## 2. General Classification Rules（通用分类原则）

### 原则 A：行为与标签分离

行为本身不等于标签。例如"主角救了敌人一次"不能直接等于"圣母"。判定前必须考虑：行为背景、合理性、重复性、后果、角色动机。

### 原则 B：事实与主观评价分离

"小说有一个系统"通常较客观；"系统存在感很强"是需要解释与判断的评价。报告必须区分事实型与评价型结论。

### 原则 C：单一事件不能随意升级成长期特征

一次剧情逻辑问题不能直接判"整本书降智严重"；一次主角吃亏不能直接判"重度虐主"。标签等级由频率、背景、合理性、后果共同决定。

### 原则 D：用户网络小说语境优先

圣母/毒点/虐主/后宫/烂尾/降智/水文等词按中文网络小说读者普遍使用方式定义；但不得把情绪化骂法写成正式事实。

### 原则 E：证据约束

任何标签的最终输出等级必须与证据强度结合（见 source-policy.md《证据标签》）。证据不足时输出 `unknown`（无法确认），不允许用模型记忆补全。

## 3. Relationship & Romance（感情相关）

### 3.1 romance-level（感情线比重）

| ID | 判定 |
|---|---|
| none | 几乎没有实质感情线。注意：**存在异性角色不等于有感情线**。 |
| low | 存在少量感情互动，但不是核心剧情驱动力，篇幅较低，不会持续占据大量章节。 |
| medium | 感情线是较稳定的重要副线。 |
| high | 感情关系是主要剧情组成部分之一。 |
| unknown | 证据不足。 |

### 3.2 romance-structure（感情结构）

| ID | 判定 |
|---|---|
| no-romance | 无实质感情线。 |
| single | 作品明确或基本明确围绕一个主要恋爱对象展开。**单女主并不意味着不存在其他女性角色喜欢主角**，只表示主角的主要恋爱对象只有一个。 |
| multiple-ambiguous | 多个角色存在明显暧昧 / 多个角色喜欢主角 / 主角与多人存在情感互动，但作品未形成明确多伴侣关系。这是重要中间分类，**不得简单写成"后宫"**。 |
| harem | 见 3.3。 |
| unknown | 证据不足。 |

### 3.3 harem（后宫）

Novel Scout 的高频雷点，必须非常谨慎。**严禁"多个女角色喜欢主角 = 后宫"**。至少区分三档：

- **H1 — 明确后宫**：主角与多个角色形成明确恋爱关系 / 婚姻关系 / 伴侣关系；作品结局明确多伴侣。
- **H2 — 强后宫倾向**：多名角色长期暧昧、主角对多人保持恋爱可能、作品明显采用后宫结构，但最终关系尚未全部确认。映射到 `romance-structure=multiple-ambiguous`，说明中提示"存在明显后宫倾向"。
- **H3 — 非后宫**：多个女性角色喜欢主角，但主角只选择一人、或完全没有回应。不能仅因此判成后宫。映射时必须继续区分：主角明确只选择一个恋爱对象 → `romance-structure=single`；主角始终没有实质恋爱回应/恋爱线 → `romance-structure=no-romance`。

判定时必须说明判到 H1/H2/H3 的理由与证据来源。

#### harem 抽象情景示例（T105 示例库，不指向任何真实小说）

**正例（应判 H1 明确后宫）**

1. 作品结尾，主角同时与两位女性成婚，正文明确承认两段婚姻关系。
2. 主角先后与三位女性确立正式伴侣关系，三人长期共同生活，正文明确其为"一家人"。
3. 作者在官方公告或作品简介中直接说明"本书为后宫文"，且正文表现与之一致。

**反例（应判 single 或 H3 非后宫）**

1. 两名女性喜欢主角，但主角明确只与一人确立恋爱关系，另一人最终退出。
2. 多名女性对主角有好感，主角自始至终未回应任何人。
3. 主角只与一人结婚，其余角色仅止步于仰慕或调侃，无实质进展。

**边界例（需进一步调查，倾向 H2 / multiple-ambiguous）**

1. 多名女性与主角长期暧昧互动，作品连载中，最终关系未定。
2. 主角与两名女性均有过"误会式亲密"描写，但作品从未确认任何关系。
3. 作品腰斩或断更，后宫结构已展开但未完成。

### 3.4 ntr（NTR / 牛头人）

极容易误判的词。等级：`none / possible / confirmed / disputed / unknown`。

以下情况**不自动等于 NTR**：

- 女角色过去谈过恋爱
- 女角色过去喜欢过别人
- 主角喜欢的人没有喜欢主角
- 单恋失败
- 前任剧情
- 男二喜欢女主
- 女主被别人追求
- 感情误会

Novel Scout 应主要将 NTR 用于：**已建立或具有明确感情承诺的关系中，出现具有背叛性质的恋爱 / 性关系转移，并构成读者通常所说的"被绿"情境。**

部分社区会把范围扩大。如果社区使用"牛头人"标签，但事实情形不符合严格定义，应输出：

> 社区中有人称其为 NTR，但按本 Skill 的严格定义存在争议。

而不是直接 `confirmed`。

### 3.5 romance-drama（感情纠纷 / 狗血程度）

等级：`none / light / medium / heavy / unknown`。

记录感情线中冲突、误会、纠葛的密度。用途：当"感情线复杂"与"雷点"难以分开时，用它客观记录感情纠纷密度，不预判对错。

## 4. Protagonist Traits（主角相关）

### 4.1 saintliness（圣母倾向）

等级：`0 none / 1 light / 2 medium / 3 high / 4 extreme / unknown`。

必须明确：

- 善良 != 圣母
- 不杀人 != 圣母
- 愿意救人 != 圣母
- 有道德底线 != 圣母

更接近高圣母倾向的行为包括：

- 在明显不合理的情况下反复宽恕重大威胁
- 因为极端道德坚持给自己或同伴造成持续重大损害
- 敌人反复造成严重伤害后仍无合理理由放过
- 角色行为和既有世界规则明显不匹配，只为了体现道德优越

任何单个事件不能直接确定整本书等级。必须考虑：频率、背景、合理性、后果、是否被作品本身批判（若作品明确批判该行为，则更可能是角色塑造而非雷点）。

### 4.2 protagonist-iq（主角智商表现）

等级：`strong / normal / inconsistent / poor / unknown`。

**不能把"主角没有采用读者知道的最优解"直接等于"降智"。** 必须考虑：角色是否知道相关信息、角色当时能否推理出来、时间压力、情绪状态、世界规则。

- strong：主角决策通常合理且有信息支撑。
- normal：偶尔疏漏，但整体符合设定。
- inconsistent：存在明显的、与设定矛盾的降智 / 开挂波动（"需要主角蠢时主角就蠢"）。
- poor：主角长期做出明显违背已有信息与自身利益的决策。
- unknown：证据不足。

### 4.3 decisiveness（果断程度）

等级：`low / medium / high / unknown`。

**杀人多 != 杀伐果断。** 更准确的理解：

- 是否能在关键冲突中做出明确决策
- 是否长期拖延必然冲突
- 是否反复因为非合理原因放弃行动

### 4.4 morality-tone（道德基调）

等级：`light / gray / dark / unknown`。

描述主角整体道德取向（描述性标签，本身不是雷点）：

- light：偏白（正义 / 光明阵营行事）
- gray：灰色（亦正亦邪，按利益行事）
- dark：偏黑（为达目的不择手段）

与 saintliness 分开：morality-tone 描述取向，saintliness 描述"圣母行为模式"的严重程度。

## 5. Plot & Structure（剧情与结构）

### 5.1 system-intensity（系统强度）

等级：`none / light / medium / heavy / unknown`。

必须明确：

- **有金手指 ≠ 有系统**：技能、遗产、体质等金手指不是系统。
- **有属性面板 ≠ heavy system**：面板只是表现形式之一。

本字段判断的是：**系统化机制对成长与剧情的控制程度**（依赖度、出现频率、对剧情主导程度）。

- none：无系统。
- light：存在系统但存在感低，仅偶尔辅助。
- medium：系统是重要机制，但剧情主要由主角与角色推动。
- heavy：系统主导剧情推进（"系统流"），任务 / 奖励构成主线。
- unknown：证据不足。

### 5.2 protagonist-abuse（虐主）

等级：`none / light / medium / heavy / unknown`。可进一步备注类型：`physical`（肉体）/ `emotional`（情感）/ `career`（事业）/ `relationship`（关系）/ `mixed`。

判定注意：必须区分**正常困难 / 正常失败 / 成长挫折**与**长期虐主**：

- 正常困难：任何主角都会遇到的阻碍。
- 正常失败：剧情需要的合理挫败，有明确原因与后续应对。
- 成长挫折：先抑后扬的铺垫，属于成长路径的一部分。
- 长期虐主：挫败程度与频率不合理、与成长脱节、反复无意义摧残。

**一次主角吃亏不等于虐主。** 等级由以下因素综合判断：

- 主角持续受挫的程度与频率
- 是否为主角核心成长路径的一部分（先抑后扬的铺垫 vs 无意义的反复摧残）
- 作者是否明显以此为爽点或虐点
- 早期铺垫型挫折与中期持续虐待应区分

### 5.3 slow-burn（慢热）

等级：`low / medium / high / unknown`。

指前期剧情展开、角色引入、爽点出现较慢。**慢热 ≠ 水文**：慢热可能来自世界观铺垫、人物建立、悬念积累、主线展开较慢——是"信息与铺垫密度"问题；水文是"篇幅与信息量不成比例"。属于体验型评价，**主要依据社区评价**。"慢热"本身不必然是雷点，是否雷由用户偏好决定。

### 5.4 filler（水文 / 注水）

等级：`low / medium / high / unknown`。

指篇幅与信息量不成比例、重复描写、拖更注水。**高度依赖社区评价**（"水不水"是主观体验），不能把个人观感当客观事实。报告应写"社区评价倾向：……"，而非断言"后期很水"。

**禁止**：字数长 → 水；章节多 → 水。必须以"单位篇幅的信息量与有效剧情密度"为判断视角，并引用社区反馈支持。

### 5.5 repetitive-patterns（套路重复）

等级：`low / medium / high / unknown`。

记录是否反复出现同类桥段：重复副本、重复打脸、重复升级、重复换地图、重复套路（如反复"先被轻视→打脸"、反复"秘境探险"）。属于评价型，依据社区评价与可核实的内容结构证据。

### 5.6 plot-logic（剧情逻辑）

等级：`strong / normal / inconsistent / weak / unknown`。

重点考察：**设定自洽、因果关系、人物行为一致性、规则是否为了剧情频繁改变**。

- strong：剧情推进大体符合设定与角色动机。
- normal：偶有瑕疵但不影响阅读。
- inconsistent：明显矛盾或"为剧情需要强行降智 / 开挂"频繁出现。
- weak：普遍存在明显逻辑漏洞，或世界观内部自相矛盾。
- unknown：证据不足。

**一次剧情漏洞不能升级为 weak**；需要频率与严重程度证据。**不能因为用户不认可角色的选择，就直接判"剧情逻辑差"**——角色选择是角色行为，逻辑差指设定与因果的断裂。

## 6. Worldbuilding（世界观相关）

### 6.1 worldbuilding-scale（世界观规模）

等级：`small / medium / large / very-large / unknown`。

客观描述世界的复杂度与展开广度（地图 / 势力 / 历史 / 规则等），不以个人喜好定性。**世界观规模 ≠ 世界观质量**：大世界可以写崩，小世界可以写精。本字段只记录规模，不评价质量。

### 6.2 power-system-consistency（力量体系一致性）

等级：`strong / normal / inconsistent / weak / not-applicable / unknown`。

主要用于玄幻、仙侠、升级流。衡量升级规则、战力设定是否前后一致。**必须保留 `not-applicable`**：大量小说（都市、日常、悬疑等）不存在力量体系，此时判 not-applicable，不做一致性评价。

- strong：体系清晰，战力边界大体稳定。
- inconsistent / weak：战力崩坏、前期神后期杂兵、设定推翻未说明等（需要频率与具体证据，不能凭一句吐槽）。

## 7. Ending & Serialization（结局与连载）

### 7.1 serialization-status（连载状态）

等级：`ongoing / completed / hiatus / discontinued / unknown`。

**事实型信息，只能尽量使用事实来源**（官方平台作品页、作者公告，见 source-policy.md Tier A）。连载中的作品表述：

> 截至当前公开剧情，未发现明确 XXX。作品仍在连载，后续可能发生变化。

不得把当前状态说成永久事实。**长期没更新 ≠ 已确认太监**：`discontinued`（断更 / 太监）必须有官方或作者相关事实来源才可确认，否则仅能标 `hiatus`（暂停）或 `unknown`。

### 7.2 ending-reception（结局评价）

等级：`positive / mostly-positive / mixed / mostly-negative / negative / unknown`。

**必须排除**（这些都不能自动等于烂尾）：悲剧结局、主角没赢、某角色死亡、用户不喜欢 CP、结局不符合个人期待。

更接近烂尾争议的证据：明显仓促收束、大量关键伏笔未处理、人物弧线突然中断、核心设定严重崩坏、结尾质量相比前文明显下降、长期多来源社区负面共识。

即使证据充分，默认表达仍优先为：**"结局评价整体偏负面"** / "结局评价：存在较明显争议"，而不是"这本书确定烂尾"。"烂尾"主要作为社区评价结果呈现，且必须是多来源共识才能写。

## 8. Confidence Interaction（证据交互与不确定性表达）

**taxonomy 等级 ≠ 证据强度，两者必须分开标注：**

- taxonomy 等级描述"这本书是什么样"。
- 证据标签（source-policy.md《证据标签》）描述"我们有多确定"。

### 8.1 四种不确定性表达（不能混用）

| 表达 | 含义 | 用于 | 示例 |
|---|---|---|---|
| UNKNOWN | 证据不足：既无支持也无可反驳的证据 | 任何标签的证据标签 / 标签值 | "是否后宫：搜不到可靠结论，标记无法确认" |
| POSSIBLE | 存在合理线索，但尚不足以确认 | 主要用作事实边界标签值（如 `ntr = possible`） | "存在暗示性的感情背叛线索，但均未确认，标记 possible；必须非常谨慎" |
| DISPUTED | 不同来源对某个分类或事实判断存在明显冲突 | 分类归属冲突 | "到底算单女主还是后宫，来源之间明显冲突（DISPUTED），不是多数投票能解决的" |
| MIXED | 社区内部评价本身两极分化 | 主要用于社区评价（如 `ending-reception = mixed`） | "结局评价：mixed，正面与负面评价各自有充分来源" |

区别要点：

- UNKNOWN 是"没查到"；POSSIBLE 是"查到线索但不够硬"；DISPUTED 是"来源之间打架"；MIXED 是"读者之间本就两极"。
- DISPUTED 与 MIXED 不可混用：一个指对"事实 / 分类"的看法分裂，一个指社区对"体验 / 评价"的两极分化。
- POSSIBLE 必须极度克制：仅靠线索不得升级为 confirmed，也不得当作"大概率是"输出。

### 8.2 证据标签输出规则

- 证据不足 → 标签值 `unknown` + 证据 `UNKNOWN`（无法确认）。
- 强证据（如官方页面确认事实型信息）→ `CONFIRMED`（已确认）。
- 多个独立来源一致（评价型）→ `LIKELY`（较可信 / 社区共识）。
- 来源冲突 → 分类层面 `DISPUTED` / 评价层面 `MIXED`（存在争议）。
- 少量弱证据 → `WEAK`（证据较弱）。

**任何标签不允许在没有证据的情况下输出非 unknown 值。**

## 9. Ambiguous Cases（边界情况速查）

| 情况 | 正确做法 |
|---|---|
| 女角色过去谈过恋爱 / 喜欢过别人 | 不判 NTR |
| 单恋失败 / 主角喜欢的人不喜欢主角 | 不判 NTR |
| 男二喜欢女主 / 女主被别人追求 / 前任剧情 / 感情误会 | 不判 NTR |
| 多个女角色喜欢主角，主角只选一人 | 判 single / H3，不判 harem |
| 多人长期暧昧但关系未确认 | 判 multiple-ambiguous，提示"后宫倾向" |
| 主角救人 / 善良 / 不杀人 / 有底线 | 不判圣母 |
| 主角一次吃亏 / 正常失败 / 成长挫折 | 不判虐主 |
| 一条评论"烂完了" | 不判烂尾（单一来源不升级为共识） |
| 悲剧结局 / 主角没赢 / 某角色死亡 / 不喜欢 CP | 不判烂尾 |
| 主角杀人多 | 不判杀伐果断 |
| 主角不按读者想法行动 | 不判降智（先查信息与推理条件） |
| 一次剧情漏洞 | 不判 plot-logic weak / 降智严重 |
| 有金手指 / 有属性面板 | 不判 heavy 系统（看系统化机制的控制程度） |
| 小说很长 / 章节多 | 不判水文 |
| 进入主线慢 | 不判水文（可能只是慢热铺垫） |
| 世界观规模大 | 不判世界观优秀（规模 ≠ 质量） |
| 有系统 | 只记录存在，系统存在感单独判断 |
| 搜索摘要"XXX 小说是一部……" | 只当线索，不当事实 |

## 11. Example Corpus（抽象情景示例库）

> 本附录用于训练与测试判定一致性。全部为抽象情景，**不指向任何真实小说**，不得把示例当作真实作品的证据。

**圣母（saintliness）**

- 正例：敌人第三次屠村后，主角仍主动放走对方并赠送财物，理由是"给他改过机会"，且作品对此不持批判态度。
- 反例：主角救下弱者并放走俘虏，是因为自身实力不足或避免更大伤亡，事后有合理权衡。
- 边界：主角宽恕一次背叛并给出第二次机会，但设置明确底线，此后不再容忍。

**虐主（protagonist-abuse）**

- 正例：主角连续多卷被反复羞辱、废去修为、亲人被害，且挫折与成长脱节，纯粹为虐而虐。
- 反例：开篇主角被退婚、被轻视，随后一路逆袭——属"先抑后扬"铺垫，判 none 或 light。
- 边界：中期一段 30 章左右的持续低谷后快速反弹——判 light / medium，备注 emotional。

**系统存在感（system-intensity）**

- 正例：主线剧情完全由"完成任务 → 获得奖励 → 接新任务"驱动。
- 反例：开篇获得一个系统，但全书仅出现 3 次，对剧情无实质影响。
- 边界：系统提供金手指但剧情由人物关系推动——判 medium。

**降智（protagonist-iq）**

- 正例：主角已获知敌人位置与计划，却多次在无压力情况下做出明显送死决策。
- 反例：主角因信息缺失、时间压力或情绪影响做出次优决策——判 normal。
- 边界：主角智商总体在线，但每隔数十章出现一次"剧情需要式犯傻"——判 inconsistent。

**烂尾争议（ending-reception）**

- 正例：结局数章内仓促收束全部势力线，多个关键伏笔无交代，社区多来源长期负面——输出"结局评价整体偏负面（存在烂尾争议）"，不直接断言"确定烂尾"。
- 反例：悲剧结局但结构完整、伏笔收齐——不构成烂尾线索。
- 边界：结局评价两极（一半人满意、一半人愤慨）——判 mixed。

**水文 vs 慢热（filler / slow-burn）**

- 正例：单章存在大量重复环境描写与数值复读，有效推进量极低——filler 线索。
- 反例：前 30 章缓慢铺垫世界观与人物，但每章都有新信息——判慢热，不判水文。
- 边界：中期开始套路化填充，更新量不变但有效信息下降——视社区反馈判 filler medium。

## 12. V1 CORE / V1 AUXILIARY 划分

为控制单次排雷的调查规模（不把每次排雷变成 20+ 项调查），标准 ID 分为两级：

### V1 CORE（16 个）— 每次排雷默认检查

romance-level、romance-structure、ntr、system-intensity、saintliness、protagonist-iq、decisiveness、protagonist-abuse、slow-burn、filler、repetitive-patterns、plot-logic、worldbuilding-scale、power-system-consistency、serialization-status、ending-reception

### V1 AUXILIARY（3 个）— 按需使用，不构成默认调查项

| ID | 用途 |
|---|---|
| harem | 派生标签：由 romance-structure 与关系事实共同推导（H1→harem、H2→multiple-ambiguous + 后宫倾向、H3→single **或** no-romance，取决于主角是否存在唯一实质恋爱对象）。不增加独立调查维度，但报告与偏好匹配必须使用（hard_no: harem 的命中规则见 preference-guide.md《偏好标签 ↔ taxonomy ID 映射表》）。 |
| romance-drama | 解释性标签：仅当感情纠纷密集且用户关心时使用。 |
| morality-tone | 描述性标签：主角道德取向，辅助解释，不参与雷点判定。 |

subtype（protagonist-abuse 的 physical / emotional / career / relationship / mixed 备注）是辅助说明，**不是独立核心字段**。

### 明确不作为 V1 字段

- **爽度**：高度个人化，无法可靠定义与取证，不作为 V1 CORE taxonomy。已记录于 PROPOSALS.md 作为未来候选。
- **毒点**：**毒点不是一个 taxonomy 字段**。毒点表示"用户个人无法接受的某个现象"（如 harem、ntr、heavy 系统、重度虐主）——这些现象对应 taxonomy 标签；是否成为"毒点"由 preference（hard_no / strong_dislike / dislike）决定。
